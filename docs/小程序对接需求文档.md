# ClinicOS 营销小程序对接需求文档（V1.0）

> 供：营销小程序开发团队 ｜ 需求方：ClinicOS 项目组 ｜ 日期：2026-08-27
> 目标：营销小程序与 ClinicOS 数据底座对接，实现「企微卡片 → 小程序 → 行为回流」闭环。
> 前置：营销小程序已关联到企业微信企业（企业微信管理后台配置，见《企业微信触达技术可行性研究报告》§5）。

---

## 1. 对接总览

### 1.1 三类页面版本（与后端三大引擎对应）
| 页面版本 | 对应引擎 | 职责 | 典型页面 |
|---|---|---|---|
| **营销类** | Recovery（唤醒）+ Growth（活动） | 展示 AI 生成的唤醒方案/活动权益 | 方案页、活动页、权益页 |
| **服务提醒类** | Retention（复诊留存） | 复诊提醒/预约确认/No-show 挽回 | 提醒页、预约确认页、挽回页 |
| **客户类（客户中心）** | 三引擎共同承接 | 客户自助：档案/预约/套餐/记录 | 客户中心、预约页、套餐页 |

> 技术建议：**1 个微信小程序主体 + 3 类页面场景**（同一套代码按场景分流）；如独立品牌/主体诉求可拆 3 个独立小程序（维护/审核成本 ×3）。企微卡片按引擎类型跳转对应页面。

### 1.2 对接流程（含内容票据）

```
企微发送小程序卡片（只携带签名票据 ticket，不携带任何内容）
        │ scene 参数透传（ticket + mp_source）
        ▼
小程序方案页 → 带 openid/ticket 调 ClinicOS 换取该客户专属内容
        GET /api/v1/mp/offer?ticket=xxx
        ▼
服务端校验（签名✓/有效期✓/绑定手机号✓）→ 返回该客户方案
        │ 埋点上报
        ▼
ClinicOS 行为回流 API（POST /api/v1/mp/events）
        ▼
行为事件 → 事件总线 → 意向评分/归因
```

小程序侧需完成三件事：**① 透传票据与场景参数；② 用票据换取专属内容；③ 埋点上报行为**。

## 2. 小程序侧改造点

### 2.1 场景参数透传
- 企微小程序卡片跳转时，携带 scene/query 参数，小程序启动时读取并透传到所有上报：
  | 参数 | 类型 | 说明 |
  |---|---|---|
  | **ticket** | string | **必填**。ClinicOS 签发的内容票据（HMAC 签名+有效期+客户绑定），小程序凭它换取该客户专属内容；**卡片不携带任何内容ID，防伪造/串号** |
  | mp_source | string | 固定值 `clinicos`（来源标识） |
  | scene_type | string | 页面场景：`marketing`（营销类）/ `reminder`（服务提醒类）/ `customer`（客户类） |
- 示例：`pages/offer/index?mp_source=clinicos&ticket=tk_xxx&scene_type=marketing`
- **注意**：campaign_id/task_id/offer_id 等业务 ID **不出现在卡片参数中**，统一由 ticket 换取

### 2.2 埋点上报
- 在关键行为点调用上报 API（见 §3），上报需携带场景参数 + 用户标识。

### 2.3 用户标识（手机号为核心关联键）
| 标识 | 获取 | 优先级 | 用途 |
|---|---|---|---|
| **mobile** | **用户授权手机号（必做）** | **最高（核心关联键）** | **全系统唯一不变标识**：企微客户 ↔ 小程序 ↔ 患者主档的统一匹配键 |
| openid | wx.login 获取 | 次 | 小程序会话标识 |
| unionid | 开放平台绑定后获取 | 次 | 跨小程序/公众号统一标识 |

> **手机号是核心**：小程序授权手机号后，ClinicOS 以手机号匹配/创建患者主档并关联企微 external_userid；patient_id 为内部稳定主键（手机号变更不影响 ID，历史绑定归档保留）。
> 关联策略：**mobile（授权后）→ unionid → openid** 依次匹配；未授权手机号仅记为匿名行为。

## 3. 内容票据换取 API（客户专属内容）

### 3.0 换取客户专属方案
- **URL**：`GET /api/v1/mp/offer?ticket=tk_xxx`
- **认证**：请求头 `X-API-Key`（ClinicOS 分配）
- **流程**：小程序启动 → 带 ticket 调用 → 服务端校验（HMAC 签名 / 有效期 / 与 openid+手机号绑定一致）→ 返回该客户专属内容

**响应（200）**：
```json
{
  "data": {
    "offer": {
      "title": "王女士的专属调理方案",
      "wecom_text": "…（与企微文字一致的方案摘要）…",
      "page": "pages/offer/index",
      "buttons": [{ "label": "预约到店", "action": "appointment_submit" }],
      "benefits": [{ "type": "coupon", "title": "老客权益·免费体质评估", "expire_at": "2026-09-10" }]
    },
    "patient": { "matched": true, "masked_mobile": "138****0000" }
  },
  "meta": { "request_id": "req_xxx" }
}
```

**错误响应**：
```json
{ "error": { "code": "TICKET_INVALID", "message": "票据无效或已过期", "retryable": false, "request_id": "req_xxx" } }
```
> 小程序收到 TICKET_INVALID 时跳转兜底页（展示通用关怀内容），并上报 page_view 供分析。

**票据规则**：
- 由 ClinicOS 在"AI 生成 → 审批通过 → 待发送"时签发
- 绑定：客户手机号 + openid + 业务（campaign/task/offer）
- 有效期：默认 72 小时（可配置）；一次性核销可选
- 用途：**保证每个客户只能换取"自己该看到的内容"**，杜绝改参数串号

## 4. 行为回流 API 契约

### 4.1 上报行为事件
- **URL**：`POST /api/v1/mp/events`
- **Content-Type**：application/json
- **认证**：请求头 `X-API-Key`（ClinicOS 分配）或登录态 Bearer
- **幂等**：请求头 `Idempotency-Key`（小程序侧建议用 event_id 或 时间戳+openid+type 拼接）

**请求体**：
```json
{
  "openid": "oXXXX",
  "unionid": "uXXXX",            // 可选，推荐
  "mobile": "13800000000",        // 可选（授权后）
  "event_type": "page_view",      // 见 §3.3 枚举
  "occurred_at": "2026-08-27T10:00:00+08:00",
  "page": "pages/offer/index",    // 页面路径
  "scene": {                      // 场景参数（企微卡片透传）
    "campaign_id": "cmp_xxx",
    "task_id": "task_xxx",
    "touch_id": "touch_xxx",
    "offer_id": "off_xxx",
    "mp_source": "clinicos"
  },
  "payload": {                    // 事件附加数据
    "duration_seconds": 12,
    "cta": "appointment_submit",
    "offer_viewed": "off_xxx"
  }
}
```

**响应（200）**：
```json
{
  "data": {
    "event_id": "mpe_xxx",
    "matched_patient": true,      // 是否匹配到 ClinicOS 客户
    "patient_id": "pat_xxx"       // 匹配到时返回
  },
  "meta": { "request_id": "req_xxx" }
}
```

**错误响应**（统一错误格式，与 ClinicOS 一致）：
```json
{
  "error": { "code": "INVALID_ARGUMENT", "message": "event_type 不在允许范围",
             "details": null, "retryable": false, "request_id": "req_xxx" }
}
```

### 4.2 批量上报（性能考虑）
- **URL**：`POST /api/v1/mp/events/batch`
- 请求体：`{ "events": [ {…同上…}, … ] }`，单次 ≤ 50 条
- 适合弱网/批量回传场景

### 4.3 事件类型枚举（V1）
| event_type | 含义 | 建议埋点位置 |
|---|---|---|
| page_view | 页面浏览 | 方案页 onLoad/onShow |
| cta_click | 按钮点击（预约/领券/拨号） | 预约按钮、领券按钮 |
| offer_view | 方案/权益详情查看 | 权益卡片展开 |
| coupon_receive | 领取优惠/权益 | 领券成功回调 |
| appointment_submit | 提交预约表单 | 预约提交成功 |
| payment_success | 支付成功（如有） | 支付回调 |
| share | 分享（转发给好友） | onShareAppMessage |
| form_fill | 表单填写 | 表单提交 |

> 枚举会随业务扩展，小程序侧需允许未知类型透传（ClinicOS 侧记录但不报错）。

### 4.4 字段字典
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| openid | string | 是 | 小程序 openid |
| unionid | string | 否 | 推荐提供，跨端统一 |
| mobile | string | 否 | 授权手机号 |
| event_type | string | 是 | §3.3 枚举 |
| occurred_at | string(ISO8601) | 是 | 行为发生时间 |
| page | string | 是 | 页面路径 |
| scene | object | 否 | 场景参数（企微透传） |
| payload | object | 否 | 附加数据 |

## 5. 页面路径约定（三类版本，与后端引擎对应）

| 页面版本 | 页面 | 建议路径 | 对应引擎 |
|---|---|---|---|
| 营销类 | 方案展示页 | pages/offer/index | Recovery / Growth |
| 营销类 | 权益/优惠页 | pages/offer/coupon | Growth |
| 服务提醒类 | 复诊提醒页 | pages/reminder/revisit | Retention |
| 服务提醒类 | 预约确认页 | pages/reminder/confirm | Retention |
| 客户类 | 客户中心 | pages/customer/index | 三引擎共同 |
| 客户类 | 自助预约页 | pages/customer/appointment | 三引擎共同 |
| 客户类 | 套餐/记录页 | pages/customer/package | 三引擎共同 |
| 通用 | 结果页 | pages/result/index | 通用 |

> 具体路径以小程序现有架构为准；ClinicOS 通过 ticket 换取内容时下发 page 字段，页面路径由小程序团队定义后回传 ClinicOS 配置。

## 6. 联调步骤

1. 小程序开发环境配置 baseURL → ClinicOS 测试环境（或本地 + 代理）
2. 拿到 X-API-Key，用 Postman/脚本调 POST /api/v1/mp/events 验证返回
3. 小程序埋点接入 → 真机触发 → ClinicOS 事件流可见（合规审计页「事件流」）
4. 企微卡片跳转联调：企微管理后台创建小程序消息 → 真机点击 → 验证 scene 参数透传
5. 全链路验证：任务 → AI 内容 → 审批 → 企微发送 → 小程序行为 → 归因（Phase 2 验收）
