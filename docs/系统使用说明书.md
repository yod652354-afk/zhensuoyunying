## 1. 系统简介

ClinicOS 不是 HIS/CRM，而是位于诊所现有系统之上的**经营决策与执行层**。它回答三个问题：

- **过去的钱**（Recovery）：哪些沉睡/流失客户值得追回？追回后多赚了多少？
- **现在的钱**（Retention）：今天的客户如何不变成明天的沉睡客户？漏损在哪一环？
- **未来的钱**（Growth）：活动到底多赚了没有？哪些动作值得复制？

核心原则：**一切价值以"增量"计算（实验组 − 对照组），不把自然回款算作系统功劳。**

## 4. 功能模块使用说明

### 4.1 经营驾驶舱（老板端首页）
**目的**：一屏看清"过去的钱 / 现在的钱 / 未来的钱"。

| 区块 | 含义 | 数据来源 |
|---|---|---|
| 可追回收入 | Recovery 池前 50 名高价值沉睡/流失的预计可追回金额（按历史消费×30% 估算） | recovery_pool |
| 本月增量追回 | 本月已完成的 Recovery 任务预计价值 + 回访转化收入 | tasks/followups |
| 今日应复诊 / 超期复诊 | Retention 计划窗口覆盖今天 / 窗口已过未到店 | treatment_plans |
| 调整后复诊率 | 窗口内实际复诊 / 到店（已剔除合理流失） | visits/care_recommendations |
| 预计增量收入 | 待执行 Growth 任务预计价值之和 | tasks |
| 本月总结果 | Incremental Recovery + Retention + Growth 汇总 | tasks |
| 员工激励榜 | 按**增量价值**排序（非任务数），含完成率 | tasks/followups |
| 异常预警 | 高价值流失、漏斗最大漏损节点、员工任务积压 | 各引擎 |
| 实验增量看板 | 全部实验的 Lift/增量收入/ROI/显著性 | experiments |

**操作**：无需操作，打开即看。数据每请求实时计算。

### 4.2 患者档案
- 全部患者主档：状态（活跃/沉睡/流失/新客/免打扰）、阶段、累计到店、累计收入、主诊医生、合规标记（DNC/投诉/已授权）
- 支持按姓名搜索、分页
- 业务含义：客户唤醒/复诊留存/营销增长的共同客户主体；修改手机号/姓名**不会改变患者 ID**（稳定唯一 ID）

### 4.3 客户唤醒池
**目的**：回答"谁最值得追回、为什么、怎么做"。

- 自动分群：初诊未复诊 / 沉睡 30 天 / 60 天 / 90 天 / 流失 180 天+
- 自动排除：DNC、投诉、无效号码（P0 合规，全局生效）
- **Score 评分**（0–100）：正向（累计到店/消费/套餐剩余）+ 负向（无效联系/投诉/近期已触达/无回应）
- 优先级：S(≥75) / A(≥55) / B(≥35) / C
- **「生成今日任务」**：把池中前 50 名转为待执行任务，自动附带：建议渠道（沉睡→企微/电话）、建议时间（次日上午）、话术模板

**业务动作**：每日 09:00 系统已自动生成（见 §4.4）；老板可随时查看池并按需点「生成今日任务」补充 → 员工在「今日任务」执行 → 实验归因。

### 4.4 今日经营任务（员工端核心）
- 统一任务流：客户唤醒 / 复诊留存 / 营销增长 / 预约 / 回访 / 老板复盘 / 医生动作
- 每任务含：类型、优先级、原因、预计价值、**建议渠道**（电话/短信/微信/企微）、建议时间、话术模板、执行人、截止时间、状态
- **状态流转**：待处理 → 开始（进行中）→ 完成并反馈 → 老板审核（通过归档 / 退回重做）

#### 任务怎么分配？（谁看诊谁负责）
1. **每日 09:00 系统自动生成**当日任务（可在 .env 的 `TASK_SCHEDULE_HOUR/MINUTE` 调整，`TASK_SCHEDULE_ENABLED=false` 关闭）
2. 分配规则按优先级：
   - 患者**主诊服务员工**（primary_staff_id，在职）优先
   - 其次患者**主诊医生**
   - 都没有则**同门店待办最少的员工**（负载均衡）
3. 自动附带：优先级评分、原因、**建议渠道 + 建议时间 + 话术模板**（话术库自动匹配）
4. **去重**：同一患者 14 天内已有同类待办/进行中任务则跳过

#### 执行反馈与后台审核
- 员工点「完成并反馈」：填写**反馈文字** + 上传**反馈图片** + 选择结果标记（有意向/已预约/已到店/已成交/无回应）→ 任务进入"待审核"
- 老板在「待审核」Tab 审核：
  - **通过** → 归档，计入员工激励与归因
  - **退回** → 任务回到"进行中"，截止时间顺延 1 天（自动催办），员工补充后重新提交
- 每次审核留痕：审核人、时间、意见；产生 task.reviewed 事件

### 4.5 复诊留存漏斗
**目的**：定位"收入漏在哪一环"。

- 过程漏斗：到店(基数) → 医生给出后续建议 → 已创建预约 → 预约履约 → 实际复诊
- 每个节点显示人数与转化率；**漏损节点自动排序**（流失最多的环节排最前）
- 今日应复诊 / 超期复诊预警列表（超期天数、建议窗口）
- 按医生/员工维度：建议率 <30% 自动标记异常（在「经营报表」页查看）

### 4.6 营销增长计划
- 活动列表：Always-on / 节气节日 / 新项目 / 唤醒，含目标（新客/唤醒/留存/套餐销售）、预算、状态
- **新建活动**：填写名称/类型/目标/预算
- **添加受众**：批量填入患者 ID，并指定实验分组（control / treatment_a / treatment_b）
- 业务含义：活动是策略容器，受众分组支撑增量归因

### 4.7 实验与增量归因
**目的**：证明"多赚的钱"。

- 实验：引擎、假设、主指标、状态
- 每组指标：样本数、回店率、收入
- **增量计算**：Lift = 实验组回店率 − 对照组回店率；增量客户 = 样本 × Lift；增量收入 = 增量客户 × 平均客单；ROI = 增量收入 ÷ 成本
- **显著性**：z 检验 + p 值 + 95% 置信区间；结论：显著 / 边缘显著 / 不显著 / **方向性**（样本不足时自动降级，不夸大结论）
- 新建实验后需通过「活动受众」或实验分组接口把人分到 control/treatment

### 4.8 经营报表（经营报表中心）
三个 Tab：

**① 漏损报表（Revenue Leakage Report）**：可追回收入、高价值沉睡数、漏损节点排序、按医生过程指标（含异常 flag）、按项目大类的到店/收入分布。**每周老板复盘必看**。页顶「触发自动任务引擎」按钮可一键把超期复诊/No-show/疗程中断生成挽回任务（对应 §5 Retention 闭环）。

**② 数据对账**：选日期 → 核对 新增患者/到店/新预约/No-show/订单金额/支付金额/退款/净收入；订单与支付不一致时**定位到具体订单 ID**。建议每日运行。

**③ 每周复盘（Learning）**：记录周期总结、保留动作、淘汰动作、下周计划，沉淀 Action→Outcome 经验。

### 4.9 数据导入与质量
**数据质量评分**：四维（完整性/一致性/时效性/授权）加权总分，≥80 可进入主实验，<60 需补数据。

**CSV 导入**：患者 / 到店 / 订单 三类模板（页面可下载模板）：
- 患者：name, mobile, gender, first_visit_date, last_visit_date, total_visits, total_revenue, contact_status, consent_status, dnc
- 到店：patient_id, visit_at, doctor_id, service_category, visit_type, first_visit_flag
- 订单：patient_id, paid_at, final_amount, original_amount, discount_amount, service_id
- 导入后自动更新患者累计到店/收入/首末次到店；质量评分即时刷新

### 4.10 合规审计
两个 Tab：

**① 授权与免打扰 · 事件流 · 投递日志**
- 统计：已授权 / DNC / 投诉 / 无效联系方式
- 事件流（最近 30 条）：业务动作事件（patient.created、payment.completed…），可「补偿重放」
- Webhook 投递日志：事件、状态、尝试次数、错误

**② 营销内容审批**
- **提交内容** → 自动**风险扫描**（7 类规则：绝对化疗效承诺/医疗广告违禁词/诱导就医/案例佐证/促销敏感/个人信息/敏感人群，按高/中/低风险计分）
- 人工**审批**（通过/驳回，留痕：审批人/意见/时间）
- 命中风险词的内容**必须人工审批**后才能发布

### 4.11 系统设置
- **Webhook 订阅**：目标 URL、事件类型过滤（留空=全部）、签名 Secret；可测试事件、查看投递日志
- **话术模板库**：按任务类型（Recovery/Retention/Growth）×渠道（企微/微信/短信/电话）维护话术；支持变量 {患者姓名} {医生} {门店}；任务生成时自动匹配

## 5. 三大引擎业务闭环（操作总览）

```
发现漏损 → 定位原因 → 生成动作 → 执行 → 归因 → 复盘
```

| 引擎 | 发现 | 动作 | 执行 | 证明 |
|---|---|---|---|---|
| Recovery | 客户池（分群+评分） | 每日 09:00 自动生成 + 「生成今日任务」补充 | 员工按建议渠道/话术触达 | 实验对比 增量 Lift/收入 |
| Retention | 漏斗漏损节点 / 超期预警 | 「经营报表→触发 Retention 引擎」自动生成挽回/提醒任务 | 员工执行 | 漏斗转化率提升 |
| Growth | 活动与受众 | 新建活动 + 添加分组受众 | 今日任务 + Touch 记录 | Campaign 归因 + 显著性 |

## 6. 对外集成（API / Webhook）

- **API 文档**：http://127.0.0.1:8001/docs（OpenAPI 3.1，可导入 Postman）
- **认证**：请求头 `X-API-Key`（服务端）或 `Authorization: Bearer <JWT>`（登录用户）
- **增量同步**：列表接口支持 `created_since / updated_since / cursor / limit / include_deleted`
- **写接口**：任务/回访/预约/标签/阶段/活动/受众/触达/实验/归因，支持 `Idempotency-Key`
- **Webhook**：标准事件包络（event_id/event_type/occurred_at/actor/object/trace_id/data），HMAC-SHA256 签名（X-Webhook-Signature/Timestamp），失败指数退避重试（后台 worker 每 60s 扫描重试），`event_id` 幂等
- **事件补偿**：`GET /api/v1/events/replay` 或按实体 `updated_since` 重拉

## 7. 常见问题 FAQ

**Q1：演示数据怎么重置？**
停后端 → 删除 `backend/clinicos.db` → 重启（自动重新生成种子数据）。

**Q2：为什么复诊留存漏斗"实际复诊"是 0？**
漏斗要求"建议后的再次到店"。演示数据中多数患者的最近一次到店就是窗口内最后一次，没有更晚的到店。接入真实数据（有连续到店史）后即有数值。

**Q3：为什么实验显示"方向性"而非"显著"？**
实验纪律（§9.2）：样本不足（<10 人/组）只给方向性结论。随着实验推进样本增加会自动升级判断。

**Q4：Webhook 为什么没真实外发？**
默认 `WEBHOOK_DELIVERY_MODE=log`（只记日志）。有接收方后改 `.env` 为 `http`。

**Q5：内容扫描能保证合法吗？**
不能。规则库是运营占位，正式商用前必须由法律团队审查（见合规清单）。

**Q6：如何接入我的 PostgreSQL？**
见 §9.1。

## 8. 数据与合规红线（操作必读）

1. **DNC/投诉/无效号码**：全局生效，任何营销队列自动排除，不要手工绕过
2. **触达频控**：同一客户 14 天内最多 1 次主动触达（系统任务已去重）
3. **内容发布**：必须经风险扫描 + 人工审批 + 留痕
4. **对外口径**：只用增量收入，不把自然回款算系统功劳
5. **数据最小化**：不导入完整病历/诊断/处方

## 10. 术语表

| 术语 | 含义 |
|---|---|
| Incremental Lift | 实验组回店率 − 对照组回店率（百分点） |
| Holdout / Control | 对照组：不触达的自然回流基线 |
| DNC | Do Not Contact：免打扰名单，全局生效 |
| Adjusted Retention Rate | 调整后复诊率：剔除合理流失（痊愈/迁居/主动拒绝） |
| Recovery Score | 客户追回优先级评分（0-100） |
| Directional Signal | 方向性信号：样本不足时的保守结论，不夸大统计意义 |
