# ClinicOS 二期规划书：企业微信触达 + 小程序闭环 + AI 个性化内容引擎

> 版本：V1.0 ｜ 日期：2026-08-27
> 定位：在现有 ClinicOS（数据底座 + 三大引擎 + 任务闭环）之上，补齐「客户触达执行层」——通过**企业微信**向客户发送**文字 + 营销小程序**，由 **AI 基于客户画像（病情等）× 消费心理学**生成个性化宣传方案并注入小程序，让 Recovery/Retention/Growth 三大引擎真正触达客户、回收行为、完成归因闭环。
> 用途：内部立项、开发排期、预算与采购、合作沟通底稿。

---

## 1. 项目目标与边界

### 1.1 一句话定义
ClinicOS 从"**内部经营决策系统**"升级为"**决策 → AI 生成 → 企微触达 → 小程序承接 → 行为回流 → 归因优化**"的**全链路客户经营闭环系统**。

### 1.2 本期唯一目标
打通一条可验证的闭环：**引擎判定客户该做什么 → AI 按病情+消费心理生成宣传方案 → 企微发文字+小程序 → 客户在小程序完成行为（浏览/预约/到店）→ 行为数据回流 → 增量归因**，并证明该链路带来可归因的增量收入。

### 1.3 明确不做（本期）
- 自建聊天机器人/客服对话（仅触达推送，不做多轮对话）
- 微信小程序从零开发（沿用你已建成的营销小程序，仅做桥接）
- 支付/交易（小程序已有或后续接入）
- 私域社群运营/朋友圈营销（聚焦 1v1 企微触达）
- 用大模型替代医生诊断（AI 只做经营内容，不做医疗建议）

## 4. AI 内容生成引擎（核心）

### 4.1 设计原则
1. **AI 生成经营内容，不生成医疗建议**——文案聚焦"回访关怀/复诊提醒/活动权益/健康知识"，疗效承诺一律禁止（合规）
2. **数据最小化**——大模型只接收**脱敏画像**（病情大类、阶段、消费区间、沉睡天数），绝不传完整病历/姓名/手机号
3. **结构化输出**——模型输出 JSON（标题/正文/小程序方案/心理策略/风险提示），强制校验后才进审批
4. **人工审批兜底**——所有 AI 内容必须过现有 ContentReview 审批流（法律要求）

### 4.2 输入特征（客户画像 → 脱敏特征向量）
| 维度 | 示例 | 来源 |
|---|---|---|
| 病情大类 | 脾胃病 / 颈肩腰腿痛 / 妇科调理 / 膏方 | patient 关联 visit.service_category |
| 治疗阶段 | 初诊 / 疗程中 / 疗程中断 / 已痊愈 | treatment_plan / package |
| 生命周期 | 活跃 / 沉睡30/60/90天 / 流失 | 一期 Recovery 分群 |
| 消费能力 | 高/中/低（历史消费区间） | total_revenue |
| 套餐权益 | 剩余次数 / 即将到期 | package.remaining/expire |
| 主诊医生 | 医生姓名（权威背书用） | primary_doctor_id |
| 历史响应 | 上次触达结果（已读/回复/拒绝） | followup.result |

### 4.3 消费心理学策略库（Prompt 注入）
| 策略 | 适用场景 | 文案示例方向 |
|---|---|---|
| 损失厌恶 | 套餐即将到期、次数快用完 | "您的 5 次调理权益还剩 2 次，到期作废" |
| 权威背书 | 主诊医生跟进 | "周医生提醒您：按疗程坚持到店效果更佳" |
| 社会认同/从众 | 节气活动、同病情客户 | "本月已有 326 位颈肩客户完成调理" |
| 稀缺性 | 活动名额、专家号 | "本期膏方预约名额仅剩 8 个" |
| 互惠 | 沉睡唤醒、新客 | "免费体质评估一次，回馈老客户" |
| 承诺一致 | 疗程中客户 | "您上次约定本周复查，我们已为您预留时间" |
| 情感共鸣 | 高价值流失 | "记得您调理后气色好了很多，最近身体还好吗？" |
| 具象收益 | 复诊提醒 | "坚持 3 次推拿，肩颈僵硬明显缓解" |

策略库**可配置、可学习**：每次触达的增量效果回填策略权重，系统自动推荐高胜率策略（Learning 闭环）。

### 4.4 大模型调用设计
- **模型选择**：境内合规优先——通义千问 qwen-plus / DeepSeek / 智谱 GLM / 豆包均可，建议 qwen-plus（中文医疗语义强、成本低）；预留多模型切换（OpenAI 兼容接口统一封装）
- **Prompt 模板**（示例，Recovery 沉睡唤醒）：
  ```
  你是中医诊所的经营顾问。为以下客户生成一条企业微信触达文案+小程序宣传方案：
  客户画像：{病情大类}、{阶段}、沉睡{days}天、消费等级{level}、套餐剩余{remaining}次、主诊医生{doctor}
  营销目标：唤醒到店（Recovery）
  消费心理策略：{策略（如损失厌恶）}
  要求：1) 语气温暖不推销；2) 不承诺疗效、不涉医疗诊断；
  3) 输出 JSON：{title, wecom_text(≤120字), mini_program:{page, params, card_title}, psychology_strategy, risk_flags}
  ```
- **输出校验**：JSON Schema 校验 + 现有风险词扫描（复用一期 compliance.py）+ 医疗违禁词二次过滤
- **兜底**：模型不可用/超时 → 回落话术模板库（一期已有）

### 4.5 生成流程
```
任务 → 画像提取(脱敏) → 策略推荐 → Prompt 组装 → 大模型调用
  → JSON 校验 → 风险扫描 → 存草稿 → 老板审批(ContentReview) → 通过 → 待发送
```

## 5. 企业微信触达执行层（WeCom Gateway）

### 5.1 前置条件（需确认/办理）
- 企业微信**认证企业**（需营业执照）
- 自建**应用**（获得 AgentId / Secret）
- **客户联系**权限（获取 external_userid，1v1 发送 + 客户群发）
- 服务器 IP 加入企业微信可信 IP
- 小程序与企微应用**关联**（小程序卡片可跳转）

### 5.2 核心能力
| 能力 | 企微 API | 用途 |
|---|---|---|
| 发送文字 | message/send（text） | 触达正文 |
| 发送小程序卡片 | message/send（miniprogram_notice / link） | 承接宣传方案 |
| 上传素材 | media/upload | 图片/文件素材 |
| 获取客户 | externalcontact/get | external_userid ↔ patient 关联 |
| 群发 | externalcontact/add_msg_template | 节日活动批量触达 |
| 回调 | 接收消息/事件回调 | 客户回复、拒收、添加好友 |

### 5.3 发送策略与防骚扰
- **频控**：沿用一期 14 天/客户 规则（全局）；单日发送上限可配置
- **发送回执**：成功/失败/拒收 → 更新 Touch.delivery_status（一期字段已预留）
- **退订/投诉**：客户回复拒收或投诉 → 自动置 DNC（一期全局生效）
- **重试**：失败自动重试（复用 Webhook 重试模式）

## 6. 小程序桥接与行为回流

### 6.1 三类小程序页面版本（与后端引擎对应）
| 页面版本 | 对应引擎 | 职责 | 典型页面 |
|---|---|---|---|
| **营销类** | Recovery（唤醒）+ Growth（活动） | 展示 AI 生成的唤醒方案/活动权益 | 方案页、活动页、权益页 |
| **服务提醒类** | Retention（复诊留存） | 复诊提醒/预约确认/No-show 挽回 | 提醒页、预约确认页、挽回页 |
| **客户类（客户中心）** | 三引擎共同承接 | 客户自助：档案/预约/套餐/记录 | 客户中心、预约页、套餐页 |

> 确认结论：**后端三大引擎 = 三类页面场景的内容生产与决策源**（Recovery→营销+服务、Retention→服务提醒、Growth→营销），客户中心为共同承接底座。
> 技术形态：**1 个微信小程序主体 + 3 类页面场景**（一套代码按场景分流，企微卡片按引擎跳转对应页面）；如独立品牌/主体诉求可拆 3 个独立小程序（维护/审核成本 ×3）。

### 6.2 客户身份：手机号为核心关联键
- **手机号 = 全系统唯一不变标识**（业务层）：企微客户 ↔ 小程序 ↔ 患者主档 的统一匹配键；小程序授权手机号后服务端以手机号匹配/创建患者主档
- patient_id = 内部稳定主键（一期 R-001：手机号变更不影响 ID，历史绑定归档保留）
- 关联策略：mobile（授权后）→ unionid → openid 依次匹配

### 6.3 内容票据机制（防串号/防伪造，安全核心）
- 企微卡片**只携带签名票据 ticket**（HMAC 签名 + 有效期 + 绑定手机号/openid + 业务ID），**不携带任何内容ID**
- 小程序凭 ticket 调 `GET /api/v1/mp/offer` 换取**该客户专属**方案（标题/正文/权益/页面路径）
- 校验失败（TICKET_INVALID）→ 跳兜底页；杜绝客户改参数看他人内容
- 票据在"AI 生成 → 审批通过 → 待发送"时签发，默认 72h 有效

### 6.4 ClinicOS 侧
| 模块 | 实现 |
|---|---|
| 内容票据签发 | ticket 生成/校验/核销（HMAC + 状态存储） |
| 专属内容换取 | GET /api/v1/mp/offer（绑定校验 → 返回客户方案） |
| 行为上报 API | POST /api/v1/mp/events（验签 + 幂等 + 批量） |
| 行为事件表 | mini_program_events（patient_id/event_type/occurred_at/payload/场景参数） |
| 归因关联 | 行为经 ticket 反查 campaign/task/touch，归因到触达 |
| 事件总线 | 行为事件并入现有 Event 流，供归因与意向评分使用 |

## 7. 三大引擎 × AI 触达闭环场景

### 7.1 Recovery：沉睡唤醒
沉睡客户(60天) → 画像：颈肩腰腿痛/疗程中断/中消费/套餐剩3次
→ 策略：损失厌恶+权威背书
→ AI文案："王女士，林医生记得您之前推拿后轻松很多，您购买的疗程还剩3次，下周三前使用还能享受老客权益，本周帮您留个时间？"
→ 企微发送【文字+小程序：体质评估方案卡】
→ 小程序点击 → 预约提交 → 到店 → 归因（Treatment vs Holdout）

### 7.2 Retention：复诊留存
疗程中客户到期日 → 策略：承诺一致+具象收益
→ AI文案："您上次说好本周复查，我们已为您预留周医生的时间，坚持完成疗程效果更佳"
→ 小程序卡片：复诊预约页 → 行为回流 → 漏斗节点更新

### 7.3 Growth：活动营销
节气活动(膏方节) → 客群：高消费+膏方相关 → 策略：稀缺性+社会认同
→ AI文案："秋季膏方节，本期名额仅剩8个，已有326位客户预约"
→ 群发小程序卡片 → 行为回流 → Campaign 归因（对照组对比）

## 9. 合规与安全（本项目最高优先级）

| 风险点 | 合规要求 | 系统落地 |
|---|---|---|
| 医疗广告 | 《医疗广告管理办法》：中医诊疗广告需审批、不得宣传疗效/保证治愈 | AI 内容强制风险扫描 + 医疗违禁词过滤 + 人工审批留痕；文案只做"关怀/提醒/权益" |
| 个人信息(PIPL) | 病情属敏感个人信息，处理需单独同意 | 大模型只收脱敏画像（病情大类，无姓名/手机号/详细病历）；触达需授权记录 |
| 营销触达 | 未经同意不得发送商业性信息 | 仅对 consent_status=granted 客户触达；DNC/投诉全局生效（一期已有） |
| 企业微信规则 | 频控/防骚扰（违规封号） | 全局 14 天频控 + 单日上限 + 退订即停 |
| 大模型数据 | 境外模型传输敏感信息风险 | 仅用境内模型；画像脱敏；不落模型侧日志 |
| 小程序审核 | 医疗健康类小程序内容审查 | 方案内容复用审批流；不合规文案自动替换为模板兜底 |

## 11. 分期实施计划

### Phase 1（第 1–6 周）：AI 内容引擎 + 企微文字触达（MVP）
- 大模型 API 接入（一家）+ Prompt 模板库 + 消费心理学策略库（8 策略 JSON）
- 客户画像提取（脱敏）与任务联动（Recovery/Retention 任务自动产出 AI 草稿）
- AI 内容结构化输出校验 + 风险扫描 + 审批流（复用一期）
- WeCom Gateway：自建应用认证、external_userid 关联、发送文字
- 发送回执/频控/退订置 DNC
- **验收**：沉睡客户收到个性化企微文字，回复/到店可归因；内容 100% 过审批

### Phase 2（第 7–12 周）：小程序卡片 + 行为回流 + 自动化
- 企微发送小程序卡片（方案注入参数）
- 小程序埋点 + 行为上报 API + mini_program_events 表
- 行为 → 事件总线 → 意向评分（浏览/预约加权）
- 审批通过后自动发送（半自动：默认人工确认，可配置自动）
- Growth 群发 + Campaign 归因接入小程序行为
- **验收**：一次完整闭环跑通（任务→AI→审批→企微→小程序→行为→归因）

### Phase 3（第 13–18 周）：优化与学习
- 内容 A/B 测试（文案/策略/时机）
- 策略权重学习（高胜率策略自动推荐）
- 多模型切换 + 成本控制（token 用量看板）
- 发送时机优化（按客户历史行为黄金时段）
- **验收**：增量 ROI 稳定 ≥5x（对齐一期 KPI）

## 17. 实施计划（细化排期）

### Phase 1（第 1–6 周）：AI 内容引擎 + 企微文字触达 MVP
| 周 | 里程碑 | 产出 |
|---|---|---|
| W1 | 环境与接口 | 通义千问 API 接入（key/限流/错误处理）；企微自建应用与可信 IP 配置；patient↔external_userid 关联脚本 |
| W2 | 画像与策略 | 脱敏画像提取服务；8 策略消费心理学策略库（JSON 可配置）；Prompt 模板库 v1 |
| W3 | AI 内容引擎 | 生成服务（结构化输出校验 + 风险扫描 + 审批流打通）；任务联动（Recovery/Retention 任务自动产出草稿） |
| W4 | 企微 Gateway | add_msg_template 封装（text 先）；发送回执/频控/退订置 DNC |
| W5 | 联调 | 真实企微环境发文字；AUTO/MANUAL 双模式；联调验证清单逐项确认 |
| W6 | 试点 | 10 家门店文字触达试点；内容 100% 过审；发送-回复-到店归因闭环 |

### Phase 2（第 7–12 周）：小程序卡片 + 行为回流 + 自动化
| 周 | 里程碑 | 产出 |
|---|---|---|
| W7-8 | 小程序对接 | 行为上报 API + mini_program_events 表 + 场景参数透传；配合小程序团队埋点（依《小程序对接需求文档》） |
| W9 | 小程序卡片 | 企微 miniprogram 消息发送（关联企业配置）；方案注入（campaign_offers） |
| W10 | 行为智能 | 行为→意向评分；行为事件并入归因 |
| W11 | 自动化 | SEND_MODE=auto 联调；审批后自动发送（或自动创建群发+提醒确认） |
| W12 | 全链路验收 | 任务→AI→审批→企微→小程序→行为→归因 完整闭环 KPI 验收 |

### Phase 3（第 13–18 周）：优化与学习（见 §11）
- 内容 A/B、策略权重学习、token 成本看板、发送时机优化
