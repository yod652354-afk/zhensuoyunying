# 企业微信触达技术可行性研究报告

> 版本：V1.0 ｜ 日期：2026-08-27 ｜ 结论：**技术可行**（含 3 项关键约束与对策）
> 目标：验证「通过企业微信向客户发送 文字+营销小程序卡片」在技术上的可行性、接口路径、限制与落地对策。

---

## 1. 结论摘要

| 问题 | 结论 |
|---|---|
| 能否向客户（外部联系人）发消息？ | ✅ 可以，走「客户联系」体系（externalcontact 系列接口） |
| 能否发小程序卡片？ | ✅ 可以，群发消息支持 miniprogram 类型，**但小程序必须"关联到企业"**（前置条件） |
| 能否完全自动发送？ | ⚠️ **受限**：企业群发接口创建后默认需**成员在企业微信客户端确认**才发送（防骚扰设计）；需联调验证或采用"成员确认"半自动模式 |
| 频控限制？ | ⚠️ 存在官方频控/防骚扰规则（客户每日接收群发上限），需联调实测确认 |
| 客户授权 | ✅ 就诊时已解决（user 确认） |
| 结论 | **可行**，推荐"AI 生成 → 审批 → 成员确认发送（或 API 直发，双模式可配）"落地 |

## 2. 官方接口路径（客户联系体系）

### 2.1 客户数据
| 能力 | 接口 | 用途 |
|---|---|---|
| 获取成员列表 | externalcontact/get_follow_user_list | 哪些员工配置了客户联系 |
| 获取客户列表 | externalcontact/list | 成员的客户列表（external_userid） |
| 获取客户详情 | externalcontact/get | 客户信息（external_userid ↔ 企业微信资料） |

参考：[获取客户列表](https://developer.work.weixin.qq.com/document/path/96314)、[获取客户详情](https://developer.work.weixin.qq.com/document/path/92114)

### 2.2 发送消息（核心）
| 路径 | 接口 | 支持类型 | 说明 |
|---|---|---|---|
| **企业群发**（推荐主路径） | externalcontact/add_msg_template | text / image / link / **miniprogram** / video / file | 向外部联系人批量发消息；miniprogram 类型可跳小程序卡片 |
| 群发结果 | externalcontact/get_groupmsg_send_result | - | 查询发送结果（送达/失败） |
| 欢迎语/自动回复 | externalcontact/send_welcome_msg | text/image/link/miniprogram | 加好友时自动欢迎语（场景有限） |
| 微信客服 | kf/send_msg | text/image/link/miniprogram | 主动发送受限：**客户咨询后 48 小时内可回复** |

参考：[创建企业群发](https://developer.work.weixin.qq.com/document/path/96366)

### 2.3 关键约束（官方文档确认）
1. **miniprogram.appid 必须是"关联到企业的小程序应用"**——需在企业微信管理后台将营销小程序关联到企业（前置配置，见 [社区说明](https://developer.work.weixin.qq.com/community/question/detail?content_id=16720512267357861464)）
2. **企业群发创建后需成员确认发送**：add_msg_template 创建的是"群发任务"，推送给成员后由成员在企微客户端确认发送（防骚扰设计）——**对"全自动"的影响见 §4**
3. **频控**：官方对客户接收群发有频控（防骚扰，详见 [2026 官方规则解读](https://college.wshoto.com/a/313422.html)），客户每日接收上限需联调实测

## 3. 架构落地建议（双模式发送）

```
AI 内容引擎生成 → 合规审批 → 发送任务（SEND_MODE 可配置）
                                    │
                    ┌───────────────┴───────────────┐
              AUTO 模式                        MANUAL 模式（推荐首选）
      add_msg_template 直发                    推送到成员企微客户端
      （联调验证可行则启用）                      成员确认即发（符合"谁看诊谁负责"）
                    │                               │
                    └───────────────┬───────────────┘
                             企微消息（文字+小程序卡片）
                             客户 → 小程序行为 → 回流
```

- **系统默认 MANUAL**（合规最稳：内容审批 + 成员人工确认，双保险），`.env` 可切 AUTO
- AUTO 需联调验证 add_msg_template 实际发送行为；若官方确认不支持直发，AUTO 退化为"自动创建群发任务 + 提醒成员确认"
- 两种模式均完整记录 Touch 发送回执

## 4. 必须联调验证的技术点（上线前清单）

- [ ] add_msg_template 创建后：消息是否自动发送？还是必须成员确认？（决定 AUTO 可行性）
- [ ] miniprogram 消息跳转参数（page + params）是否透传到小程序？（scene 参数）
- [ ] 客户每日接收群发上限实测值（防骚扰触发阈值）
- [ ] external_userid 与现有 patient 表关联的批量导入/同步方式（一期 patient.enterprise_wechat_id 字段对接）
- [ ] 发送失败/被拒收的回执字段与重试策略
- [ ] 群发创建接口的速率限制（QPS）与批量上限（单次最多客户数）

---

## 5. 前置配置清单（需企业微信管理员/小程序团队配合）

1. 企业微信认证企业 ✅（已确认）
2. 创建自建应用（获取 AgentId/Secret），配置客户联系权限
3. 服务器公网 IP 加入企业微信**可信 IP**
4. **营销小程序关联到企业**（管理后台 → 应用管理 → 关联小程序）——关键前置！
5. 客户联系"成员"配置（哪些员工可见客户并发送）
6. 获取企业 corpid，配置到 ClinicOS 的 .env
