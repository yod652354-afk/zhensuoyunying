## 3. 产品目标

RevOS 是大健康门店的大数据自动运营平台：

```text
自动接收诊所SaaS经营数据
→ 为客户建立持续更新的经营档案
→ 判断未来/现在/过去三种钱状态
→ 发现、去重并排序经营机会
→ 结合有证据的消费心理策略生成完整执行方案
→ 自动合规检查
→ 人工审核
→ 员工企微确认执行
→ 自动收集回复、预约、到店、支付和退款
→ 计算增量收入
→ 通过实验、版本、影子运行和灰度发布持续进化
```

## 4. 系统边界

诊所SaaS是患者资料、预约、到店、疗程、订单、支付和退款的事实主系统。API需求已下发，不重新建设这些功能。

RevOS负责：

- 经营数据适配；
- 客户经营档案聚合；
- 生命周期和三种钱状态；
- Opportunity；
- Decision；
- 消费心理策略；
- ExecutionPlan；
- 人工审核；
- 外部执行编排；
- Outcome；
- 增量归因和学习。

## 6. 使用方式

本工程包采用一次性完整开发模式。将整个工程包与现有源码目录一并提供给 DeepSeek，要求在一个开发任务中完成全部 RevOS 升级，不按产品阶段拆分交付。

内部仍应按照依赖顺序实施和验证：安全基线 → 数据模型 → 客户状态机 → Opportunity → Decision → ExecutionPlan → 审核与执行 → 结果与学习；但这些只是同一次开发中的工程检查点，不是多期项目。

DeepSeek必须：

1. 先读取全部现有实现并形成修改清单；
2. 一次性完成后端、前端、迁移、接口、事件和测试；
3. 复用现有代码，不创建平行系统；
4. 在开发过程中持续运行测试，最终统一交付；
5. 最终报告全部修改文件、数据库迁移、接口、页面、测试和遗留风险；
6. 不得以“后续阶段”代替本规格要求的功能。
