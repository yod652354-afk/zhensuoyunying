## 4. 客户经营档案

每个线索、咨询、预约或到店客户自动创建/匹配稳定客户经营档案。

诊所SaaS仍是患者资料、医疗业务、预约、到店、订单、支付、退款和套餐的事实主系统。RevOS建立经营聚合视图，不复制完整病历。

必须实现：

- CustomerIdentity；
- 源系统客户ID映射；
- 手机号变更历史；
- 企微external_userid；
- 小程序openid/unionid；
- 客户价值快照；
- 生命周期时间轴；
- 三种钱迁移历史；
- 机会、方案、执行、结果和归因时间线。

## 5. 每位客户全生命周期状态机

状态至少包括：

```text

booked

```

每次关键事件实时重算，另有每日补偿重算。每次迁移保存：from/to、触发事件、reason_codes、规则版本、时间和上下文快照。

## 6. 三种钱价值循环

每个客户都持续进入判断循环，但没有合格机会时不得触达。

```text
未来的钱 → 获客转化 → 现在的钱
现在的钱 → 服务/复购 → 继续现在的钱
现在的钱 → 转介绍 → 产生新的未来的钱
现在的钱 → 风险/流失 → 过去的钱
过去的钱 → 回复/意向 → 未来的钱
过去的钱 → 重新到店/支付 → 现在的钱
```

三种钱是Opportunity分类，不是客户唯一标签。同一客户可有多个机会。

## 7. Opportunity Engine

统一实现future/current/past Detectors。现有Recovery和Retention改造成Detector，不再直接各自创建任务。

Opportunity保存：

- money_type；
- scenario_type；
- lifecycle_state；
- priority_score；
- expected_revenue、probability、cost；
- reason_codes；
- context_snapshot；
- detector/scoring/workflow版本；
- experiment/group；
- owner；
- status和expires_at。

必须实现去重、过期、抑制、重新打开和幂等。

## 8. 触达仲裁器

对同一客户所有Opportunity统一处理：

- DNC/投诉/授权；
- 近期触达；
- 机会冲突；
- 价值优先级；
- 门店产能；
- 员工负载；
- 实验组；
- 渠道限制。

同一运营周期只产生一个主要外部ExecutionPlan。其他机会保留、合并、延后或抑制。

## 9. 消费心理策略引擎

基于行为证据输出策略响应倾向，不做人格化心理标签。

首版策略：

- doctor_trust；
- rights_reminder；
- convenience；
- risk_reduction；
- care_and_empathy；
- reciprocity；
- commitment_consistency。

每项输出evidence、confidence、sample_size和avoid。禁止虚假稀缺、虚假社会认同、恐惧诱导和高压销售。

## 10. Decision与ExecutionPlan

Decision从系统允许的动作中选择，不得绕过规则。

ExecutionPlan必须包含：

- 客户状态；
- 机会及价值；
- 判断原因；
- 心理策略和证据；
- 经营目标；
- 2—3个候选方案；
- 选择的方案；
- 多步骤执行流程；
- 渠道、时间和员工；
- 文案、图片和小程序承接；
- 优惠引用；
- 停止和升级人工条件；
- 风险检查；
- 实验组；
- 预计成本和增量价值；
- 不可变版本和内容哈希。

## 11. AI内容生成

实现可替换的TextGenerationProvider和ImageGenerationProvider。

要求：

- 只传脱敏经营特征；
- 结构化JSON Schema输出；
- 超时、有限重试、成本记录；
- 模板兜底；
- Prompt、模型、参数和内容版本；
- 不生成医疗诊断、处方和疗效承诺；
- 图片、文案、权益和页面均属于ExecutionPlan版本。

具体供应商配置通过环境变量注入，不写死密钥。

## 12. 自动检查和人工审核

自动检查：结构、敏感信息、医疗广告、绝对化、虚假数字、优惠真实性、授权、DNC、投诉、频控、产能和实验组。

人工审核的是完整ExecutionPlan，不只是文案。

状态：

```text
draft → machine_checked → pending_review
→ approved / rejected / changes_requested
```

批准版本不可修改；任何修改创建新版本并重新审核。支持低风险同模板批量审核和高风险逐条审核。
