# 给 DeepSeek 的一次性修复提示词

你现在负责对 RevOS 做一次性修复和继续开发。源代码目录为：

    D:\个人文件\下载\诊所决策系统

请先完整阅读本工程包内的所有文件，尤其是总指令、开发要求、验收门禁、代码审核报告和原 V2.2 开发规格。

## 目标

一次性把 ClinicOS 完成到可验收的 RevOS：自动采集诊所数据；为每个到店客户建立统一档案并做全生命周期管理；按“未来的钱、现在的钱、过去的钱”识别机会；结合规则、统计模型、AI 和消费心理策略生成执行方案；企微外发进入人工审核；结果自动回流并用于正确归因、实验评估和策略迭代；后台任务具备可恢复、可审计、可重放能力。

## 强制要求

- 修复审核报告中的全部 P0 和 P1，不允许只改文档。
- 所有场景统一走：业务事实 → 客户状态 → 机会 → 冲突仲裁 → 执行计划 → 合规校验 → 人工审核 → 渠道执行 → 结果回流 → 归因 → 学习。
- 禁止旧召回/留存任务绕开统一机会和审核链路。
- 对照组只能禁止主动干预，不能丢弃自然到店、支付和复购结果。
- 同一事实不得广播成多个机会的胜利，必须建立可审计的事实—结果关联。
- 浏览器端不得保存服务端 API Key，前端统一使用安全登录会话。
- 企业微信真实通道必须具备回执/回调、状态映射、幂等和重试语义。
- 后台任务必须持久化，支持租约、重试、死信、重放和多实例安全执行。
- 数据库补齐外键、唯一约束、幂等约束及迁移测试。
- 不得删除测试、放宽断言、吞掉异常或屏蔽告警来制造通过。
- 不得遗留 TODO、空实现、固定返回值或只适用于演示环境的关键路径。
- 除真实账号、密钥和第三方审批外，不得把代码内可完成事项列为待办。

## 实施方式

按工程包要求连续完成开发，不按多期拆分交付。可以内部按依赖顺序施工，但最终只提交一个完整可运行版本。同步维护数据库迁移、API 契约、自动化测试、运维配置说明、产品决策记录、开发报告和 P0/P1 闭环表。

## 最终验收输出

1. 修改文件清单；
2. 数据库迁移及升级/回滚验证；
3. 审核问题逐条闭环表（问题、修复文件、测试证据）；
4. 新增能力清单；
5. 后端、前端、迁移及关键端到端测试的真实命令和结果摘要；
6. 未完成项；如果没有，写明“无代码侧未完成项”；
7. 外部依赖，仅限账号、密钥、网络白名单和第三方审批；
8. 更新后的 RevOS一次性开发报告.md。

只有全部强制门禁通过，才可以声明“开发完成”。
